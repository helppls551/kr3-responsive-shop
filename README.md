# Учебный frontend-проект 
## Описание 
Проект выполняется в рамках дисциплины «Фронтенд и бэкенд разработка». 
Тема проекта: многостраничный сайт интернет-магазина или каталога услуг. 
## Структура проекта

- `index.html` — главная страница;
- `catalog.html` — каталог товаров;
- `contacts.html` — контактная информация;
- `product.html` — единая страница трёх товаров с переключением по якорю;
- `order.html` — форма заявки;
- `css/responsive.css` — адаптивные стили;
- `css/style.css` — файл стилей;
- `js/main.js` — файл JavaScript;
- `images/` — папка для изображений;
- `README.md` — описание проекта;
- `.gitignore` — список файлов, исключённых из Git.

## Используемые технологии 
- HTML; 
- CSS; 
- Git; 
- GitHub.
## Использование Flexbox и Grid

В проекте используются:

- Flexbox для основного меню;
- Flexbox для внутренней структуры карточек товаров;
- CSS Grid для сетки карточек;
- CSS Grid для страницы каталога с фильтрами и списком товаров.

## БЭМ-структура проекта

В проекте используются следующие БЭМ-блоки:

- `site-header` — шапка сайта;
- `site-nav` — основная навигация;
- `breadcrumbs` — хлебные крошки;
- `hero` — первый экран главной страницы;
- `products-grid` — сетка товаров;
- `product-card` — карточка товара;
- `catalog-layout` — структура страницы каталога;
- `catalog-filters` — фильтры каталога;
- `order-dialog` — модальное окно заявки;
- `order-form` — форма заявки;
- `button` — кнопка;
- `site-footer` — подвал сайта.

## Практическая работа №13 — A11y-аудит и Lighthouse

**Основа:** репозиторий `kr3-responsive-shop`, продолжение практической №12.

### Исправления доступности

- На всех пяти страницах добавлена ссылка «Перейти к основному содержимому», доступная по клавише Tab.
- У `main` установлен `id="main"` для перехода по ссылке; добавлен `tabindex="-1"` для корректного фокуса.
- Приведена в порядок иерархия заголовков, включая единственный `h1` на `product.html`.
- Текущая страница в меню отмечена `aria-current="page"`; сохранена семантическая навигация `nav`.
- Для интерактивных элементов настроен заметный `:focus-visible`.
- Проверены смысловые `alt` у изображений, таблицы с `caption` и `scope`.
- Улучшена контрастность второстепенного текста.
- В формах обязательные поля явно помечены, ошибки имеют текст, `aria-describedby` и актуальное `aria-invalid`.
- Модальное окно остаётся нативным `<dialog>` с заголовком и кнопкой закрытия; клавиши Tab и Escape поддерживаются браузером.
- Проверяемые страницы: `index.html`, `catalog.html`, `product.html`, `order.html`, `contacts.html`.

### Lighthouse

**Lighthouse-аудит необходимо запустить в Chrome DevTools вручную.**
После запуска сохранить HTML-отчёт или скриншот в `lighthouse/` (см. инструкцию в этой папке).
Отчёт не создавался автоматически, поэтому оценка Accessibility не заявляется.

### Ручная проверка

Проверить последовательность Tab, ссылку пропуска, открытие/закрытие диалога, валидацию формы,
переходы в каталог и на страницы трёх товаров. Повторить на ширинах 360, 430, 768, 1024 и 1440 px.

### Git и Pull Request

```bash
git switch -c feature/a11y-lighthouse-audit
git add .
git commit -m "fix: improve accessibility and add Lighthouse report"
git push -u origin feature/a11y-lighthouse-audit
```

После добавления **реального** Lighthouse-отчёта создать Pull Request
`feature/a11y-lighthouse-audit` → `main` с заголовком
`Improve accessibility and add Lighthouse report`.
